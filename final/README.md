# `final/` — every number in REPORT_glue_beir_rankify.docx

Generated 2026-09-02 (ICT) alongside the report itself. The generator exec's the report
generator and reads the same objects the docx was rendered from, so these values are the
report's values, not an independent recomputation. Verified: 354 rendered cells checked
against this folder, 0 mismatches.

## Layout

```
final/
  all_numbers.csv          every number, one row per (section, model, task, stat, scope, seed)
  glue/<model>/<task>.json one file per reported GLUE cell
  glue/averages.json       the GLUE avg (8) row, per model and per statistic
  beir/<dataset>.json      NDCG@10 per BEIR dataset
  beir/summary.json        MEAN (15), MEAN (14, zero-shot), and the beats-public-DPR counts
  rankify/<cell>.json      exact match per (dataset, model) cell
  rankify/summary.json     common-cell means
```

## GLUE cell files

`ours` holds the four statistics. Each present statistic carries the value as printed in the
docx, the run it was taken from, and **every per-seed result the statistic was computed over**,
with the source JSON path for each seed:

```json
"med_val": {
  "value": 70.38246444016227,
  "printed": "70.4",
  "run": "paper_sweep:lr2e5_bs32_w100_p1c1",
  "n_seeds": 5,
  "selection": "median over seeds",
  "selected_seeds": [46],
  "per_seed": {"42": {"value": 69.75, "source_file": "master_deberta_large/..."}, ...}
}
```

`selected_seeds` is the seed whose result *is* the reported median. Where a statistic has an
even number of seeds the median is the average of the two middle results, so two seeds are
listed. Seed counts are 5 except for nine roberta-large entries (3, 7 or 8) whose sweeps were
stopped at different points — these are unchanged from the previous report.

`comparator` is the second half of each `ours / published` cell. For `bert-large`,
`roberta-large` and `deberta-large` it is `kind: "published"` and carries the paper values. For
the three base models it is `kind: "fresh_baseline"` and carries the full per-seed detail of our
own non-JEPA baseline, in the same shape as `ours`.

## Caveats carried over from the report

- Each statistic is maximised independently over runs, so `med_val` and the test statistics for
  one cell often come from **different runs**. The `run` field records which.
- MNLI-transfer runs are excluded everywhere; all results are single-task. For `deberta-large`
  this removes the `mnli_transfer/` tree and `second_run`'s `transfer_*` / `lr2e5_transfer_*`
  tags (2,307 result files). Its `notransfer_*` tags are own-encoder runs and are kept.
- `deberta-large` has no WNLI run, and the AdvGLUE paper has no DeBERTa row, so its WNLI cell
  and its published test cells are blank.
- STS-B values are Pearson, CoLA is Matthews correlation, everything else accuracy. AdvGLUE
  test figures are accuracy only.

## Added 2026-10-05 (not in the docx): `beir_arms/`, `tapt/`, `beir_arms_tapt_numbers.csv`

Generated by `make_beir_arms_tapt.py` (re-run it to refresh; it only reads result files).

- `beir_arms/<dataset>.json` — NDCG@10 for the three DPR pretraining objectives, each at DPR
  ckpt2 and ckpt39, from the **QA-corpus arms** (`experiment/dpr_qapre`): pretrain on the DPR
  multiset passages themselves (title/passage segment pair, one epoch = 48,886 steps, lr 5e-6,
  batch 128), then DPR bs256 x 40 epochs. `jepa` (knn_weight 0.1), `knn0` (knn_weight 0.0), `mlm`
  (BERT masked-LM, pretrained head). `public_dpr` is copied from `beir/`. `summary.json` has
  MEAN(14 zero-shot), beats-public-DPR counts and checkpoint-matched per-dataset wins. **No QA arm
  was run on msmarco**, so MEAN(15) is null. (A cold-head mlm variant also exists in dpr_qapre
  and is not included.)
- `tapt/<task>.json` — Don't-Stop-Pretraining tasks under the paper's names (CHEMPROT, RCT,
  ACL-ARC, SCIERC, HYPERPARTISAN, AGNEWS, HELPFULNESS = our `amazon`, IMDB) with the paper's
  RoBERTa/TAPT values (Table 5). Per arm (jepa, knn0): the best finished 5-seed run by test F1 at
  the best-dev epoch, its per-seed values + source files, and every candidate run's mean. Picking
  the best run by test is optimistic. `summary.json` has the 8-task means.
